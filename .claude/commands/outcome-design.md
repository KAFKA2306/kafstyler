# Outcome Design

1. Picture a specific person opening the usual page, file, command, or device and completing the task. State what they can see or do in one sentence.
2. Open the current artifact through that entry point and compare it with the intended scene. Choose the one obstacle with the largest effect on the result.
3. Set the smallest acceptance check that proves the scene and identify the existing tools that can act and observe it.
4. If the request is to execute, carry out the authorized change and repeat the same user action. Record the relevant before/after observation and where to verify it.

For a public page, put the visitor's main answer or action first, present the real data with definitions and sources, and follow the published path. Read 登大遊's article in [MISSION.md](../../MISSION.md) for the approach of imagining the desired software first.
