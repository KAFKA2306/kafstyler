# 評価と比較

任意の出力で人が読む文章には[imozの執筆・推敲ルール](../../BIBLES.md#imozの日本語編集)を適用する。[出力の共通基準](../../MISSION.md#出力の共通基準)

1. フロントエンドで既に決めた評価を、同じ用事・合格条件・測定方法で繰り返す場合は、確認済みの資料を再利用する。評価条件が変わる場合や参照する仕様が更新された場合は、影響する論点を調べ直す。

   新しく評価を設計するときやフロントエンド以外を評価するときは、対象分野の外部ベストプラクティス、開発元や規格団体の公式ドキュメント、指標の計算やばらつきの扱いに使える数理モデル、実行時点の今月に公開された関連論文を調べる。使う資料は原典を読み、一次URL、公開日または版、評価の設計に反映する点を記録する。今月の論文は原典で公開日を確認し、該当がなければ検索範囲と結果を記録する。検索できなかった項目は未確認とし、評価結果を暫定として扱う。
2. 重大な失敗と改善を測る指標を決める。指標ごとに入力、測定方法、単位と合格条件の案を作る。普段の入力のほか、結果が変わる境界や過去の失敗から評価に効く事例を選ぶ。[共通の連携手順](../../AGENTS.md#コマンドの連携)に従い、評価条件を確定する前に [`kafstyler:scrutiny`](../scrutiny/SKILL.md) を呼ぶ。指標、合格条件、比較条件、既知の不合格例を渡し、欠陥があっても合格する入力や判定を探す。判別に使える反例を評価に組み込み、条件を固定してから測る。
3. 利用者の入口から、提出するファイル、版、公開先など実物を使って確認する。比較する場合は現行か初稿と候補に同じ入力、手順、設定を使う。文書なら読者が必要な情報を見つけ、記載どおりに判断・操作できるか試す。データなら件数や合計を原データと照合する。コードなら対象の失敗を検出できる操作か既存テストを実行する。Web UIでは[画面の評価](#画面の評価)に従う。
4. 自動判定を新設・変更した場合は、既知の不合格例を落とし、合格例を通すことも確かめる。人が判断する項目は観察項目を明記し、必要に応じて、実装者の結論を伏せた状態で実物を評価する。ばらつきが採否を左右する場合は測定を繰り返す。
5. 各必須項目の合否または未確認を記録し、対象の版、差、再実行コマンドか原典を添える。必須項目の不合格や未確認が残れば全体は合格にしない。品質向上は、必須条件を満たし、重大な退行がなく、事前に選んだ指標が比較基準より良くなった場合に示す。
6. 不合格を直せる範囲では修正し、同じ入力と影響を受ける既存の確認をやり直す。比較対象や実行環境が得られない場合は、実行できた確認と再開条件を示す。

報告書や読者向けブリーフの作成まで依頼されている場合は、[`kafstyler:humanizer`](../humanizer/SKILL.md) を呼ぶ。原稿、読者、測定値、合否、未確認事項を渡し、推敲した報告を返す。

呼び出し元がある場合は、合否と測定結果を元の作業へ返す。

## 画面の評価

普段の入口で評価対象の版を表示し、変更が影響する画面幅、入力方法、状態で主要な操作を最後まで試す。[かふかのデザインパターン](../../BIBLES.md#かふかのデザインパターン)の画面評価ガイドを使う。

見た目の改善を頼まれた場合や、変更が情報の並び、操作の見つけやすさ、文字の読みやすさに影響する場合は、変更前に見た目の合格条件を決める。最も影響の大きい箇所を直し、前後の実画面を同じ条件で比較する。見た目の判定と操作の結果を別々に記し、前後の画像と対象版を添える。比較できなければ、見た目は未確認と記す。

## 定期実行と再開の評価

[常駐エージェントの聖典](../../BIBLES.md#常駐エージェント)を参照し、[自律開発の実行手順](../deliver/SKILL.md#常駐エージェントと定期実行)で選んだ入口と成果の正本を使う。通常の起動で利用者に成果が届くことを確かめる。変更が関わる場合は次の事例を加える。

| 入力と条件 | 合格と分かる結果 |
| --- | --- |
| 書き込みが反映された直後に応答が途切れ、同じイベントを再送する | 状態を読み戻して再開し、成果と外部への書き込みが各1件のままになる。 |
| 同じ正本を更新する次の実行が、前の実行中に起動する | 同時に書き込む実行が1件以下になる。待っていた実行は先行分を反映した状態から判断する。 |
| 作業を途中で止め、別セッションで同じ案件を開く | 最後に確認した成果と次の工程が分かり、未完了の工程から進められる。 |
| 起動受付の後に処理が失敗する、または必要な権限が拒否される | 成果確認済みにならず、必要な対応を追跡できる。回答が必要なら、回答後に同じ案件を再開できる。 |

実行数に加え、成果の件数、再開後の重複件数、利用者の確認にかかった時間から、変更に効く指標を選ぶ。
