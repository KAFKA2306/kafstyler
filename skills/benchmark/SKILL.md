# 自動評価

任意の出力で人が読む文章には[imozの執筆・推敲ルール](../../BIBLES.md#imozの日本語編集)を適用する。[出力の共通基準](../../MISSION.md#出力の共通基準)

1. 評価を設計・実行する前に、対象分野の外部ベストプラクティス、開発元や規格団体の公式ドキュメント、指標の計算やばらつきの扱いに使える数理モデル、実行時点の今月に公開された関連論文を、毎回すべて検索する。使う資料は原典を読み、一次URL、公開日または版、評価の設計に反映する点を記録する。今月の論文は原典で公開日を確認し、該当がなければ検索範囲と結果を記録する。検索できなかった項目は未確認とし、評価結果を暫定として扱う。
2. 重大な失敗と改善を測る指標を決める。指標ごとに入力、測定方法、単位と合格条件を評価前に固定する。普段の入力のほか、結果が変わる境界や過去の失敗から評価に効く事例を選ぶ。[レビューの指摘](../scrutiny/SKILL.md)も参照する。
3. 利用者の入口から、提出するファイル、版、公開先など実物を使って確認する。比較する場合は現行か初稿と候補に同じ入力、手順、設定を使う。文書なら読者が必要な情報を見つけ、記載どおりに判断・操作できるか試す。データなら件数や合計を原データと照合する。コードなら対象の失敗を検出できる操作か既存テストを実行する。
4. 自動判定を新設・変更した場合は、既知の不合格例を落とし、合格例を通すことも確かめる。人が判断する項目は観察項目を明記し、必要に応じて、実装者の結論を伏せた状態で実物を評価する。ばらつきが採否を左右する場合は測定を繰り返す。
5. 各必須項目を合格、不合格、未確認のいずれかで示し、対象の版、差、再実行コマンドか原典を添える。必須項目の不合格や未確認が残れば全体は合格にしない。品質向上は、必須条件を満たし、重大な退行がなく、事前に選んだ指標が比較基準より良くなった場合に示す。
6. 不合格を直せる範囲では修正し、同じ入力と影響を受ける既存の確認をやり直す。比較対象や実行環境が得られない場合は、実行できた確認と再開条件を示す。

報告書や読者向けブリーフの作成まで依頼されている場合は、[`kafstyler:humanizer`](../humanizer/SKILL.md) を呼ぶ。原稿、読者、測定値、合否、未確認事項を渡し、校正した報告を返す。

呼び出し元がある場合は、合否と測定結果を元の作業へ返す。
