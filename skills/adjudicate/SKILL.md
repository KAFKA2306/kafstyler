# 比較と採否

好みや自己採点だけで選ばない。依頼された意思決定に必要な既存の観測、一次資料、費用、制約を比較する。独立した検証工程や採点制度は作らない。

## 判断の根拠

[MISSION](../../MISSION.md) を目的、[AGENTS.md](../../AGENTS.md) を共通規約とし、利用者の明示した目的・必須制約・認可の範囲内で判断する。目的と規約に反する候補は採用しない。

- [かふかの原典](../../bibles/kafka-zenn.md)：判断箇所と重複を減らし、実行可能性と採用可否を区別する。
- [使命・評価・執筆](../../bibles/mission-eval-writing.md)：AdamsほかとYAGNIに基づき削除・統合・現状維持も比較する。AAPOR、Bisbeeほか、Huangほかを根拠に観測・合成回答・推測を区別し、根拠のない自己採点に依存しない。
- [設計とUI](../../bibles/design-and-ui.md)：利用者の目的全体と情報需要からUI・文章の採否を決める。
- その他の専門領域は [聖典台帳](../../BIBLES.md) の該当原典を適用条件と限界に応じて参照する。原典は共通規約を上書きしない。

採否の根拠には、判断に用いた原典・観測・比較条件を示す。必須制約を満たす候補の中で目的への寄与と費用を比較し、同等なら簡潔で保守負担の小さい既存方式を優先する。

## 比較手順

1. 利用者の目的、対象、必須制約、入口、予算、期限を [reconceptualize](../reconceptualize/SKILL.md) または依頼から定める。
2. 現状維持、既存実装、代替手法を候補とし、比較する単位・粒度・環境・時点をそろえる。既存実測と推測を区別し、後から都合よく基準を変えない。
3. 品質、利用者の操作、費用、処理時間、保守、障害時の影響から目的に効く判断軸を選ぶ。必須制約を満たさない候補を外し、性能と費用のパレート劣位を除く。比較不能な数値を単純合計しない。
4. 採用候補に不利な根拠と最有力代替案を考慮する。[disprove](../disprove/SKILL.md) の反例を判断に反映する。根拠不足を明示し、採用・条件付き採用・保留・不採用を区別する。
5. 採否、根拠、最有力代替案、制約、結論が変わる条件を返す。採用結果は [autocatalyze](../autocatalyze/SKILL.md) へ渡す。

## 対象別の判断軸

| 対象 | 判断に使う情報 |
| --- | --- |
| UI・文章 | 利用者の問い、情報の見つけやすさ、操作、読みやすさ、アクセシビリティ |
| API・CLI・データ | 入出力、粒度、重複・欠損、失敗時の状態、依存、費用 |
| 知識・白書 | 正本・出典への到達、比較条件、反例、適用限界 |
| 画像・音声・3D | 用途、寸法、尺、形式、品質、制作・公開費用 |
| 常駐 | 一周期の成果、期限、取り込み漏れ・重複、再開、LLM利用量 |
| モデル | 外部スコア、単価、利用枠、実行ID、必要品質、パレートフロント |

人間の好みでは実測回答と合成回答を区別する。[SSR原著](https://arxiv.org/abs/2510.08338) の自由記述・意味類似度による分布を適用条件付きの候補とし、実測なしに選好や販売を予測できるとしない。

モデル選定は利用先の設定を正本とし、mise run model-select --policy PATH を使う。[実行契約](../../commands/agents.md)。
