# 目標設定

任意の出力で人が読む文章には[imozの執筆・推敲ルール](../../BIBLES.md#imozの日本語編集)を適用する。[出力の共通基準](../../MISSION.md#出力の共通基準)

1. 利用者が普段の画面、ファイル、コマンド、機器を使う場面を思い描く。最終的に何を見て何ができるかを一文にする。画面を設計するときは、利用者が最初に見る文言、次に押す場所、用事が済んだと分かる表示を具体的に決める。
2. 同じ入口から現行の成果物を確認し、結果に最も影響する障害を一つ選ぶ。
3. 成功と判断できる観測を明確にし、実行と検証に使う既存の道具を選ぶ。時間や費用を要する作業では、上限と停止条件も決める。
4. 品質を上げる依頼では、現行や初稿を比較基準にする。読者の理解、操作の成功、精度、所要時間など、利用者の結果を左右する指標を一つ以上選ぶ。合格条件と改善を比べる指標を作業前に定める。

[共通の連携手順](../../AGENTS.md#コマンドの連携)に従い、完成場面と合格条件の案をまとめたら [`kafstyler:scrutiny`](../scrutiny/SKILL.md) を呼ぶ。 利用者が用事を済ませられなくても合格する例がないか、普段の入口と観測する結果を渡して確かめ、条件を修正する。

候補の比較まで依頼され、実行可能な入力がある場合は、[`kafstyler:benchmark`](../benchmark/SKILL.md) を呼ぶ。現行と候補、入力、合格条件を渡し、結果を目標の妥当性の判断に使う。

完成場面、合格条件、道具を示す。

## 成果物の確認と手順の改善

1. 成果物がある依頼では、[`kafstyler:benchmark`](../benchmark/SKILL.md) を呼び、実物、合格条件、利用者の入口、比較基準を渡す。人向けの文書では [`kafstyler:humanizer`](../humanizer/SKILL.md) を呼び、読者の操作や判断に必要な情報を確かめる。変更した箇所に関係する確認を再実行する。品質向上が目的で改善が観測できなければ、効果が最も見込める変更案を一つ試し、同じ条件で採否を決める。
2. 不合格の原因が成果物にあれば成果物で直す。Kafstylerの手順や起動に再現できる漏れがあれば、使用した版、再現入力、期待と実際の差を記録する。[更新手順](../../MISSION.md#更新手順)に従い、利用者が認可した範囲で正本の既存手順を最小限修正し、元の事例と別分野の事例で評価する。
3. 正本へ反映できる場合は通常の反映経路を使い、反映版を読み戻す。反映できない場合は許可された非公開の記録先か利用者への報告に再現手順と修正案を残す。元の依頼で進められる作業は続ける。
