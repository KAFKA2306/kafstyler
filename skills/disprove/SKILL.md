# 反証

主張を無条件に支持せず、成立しなくなる条件を探す。反証は依頼された調査・設計判断そのものであり、全作業に追加する検証工程ではない。

1. 反証する主張、前提、対象、利用者の目的を特定する。最も有力な対立仮説を立て、何が両者を区別するか考える。
2. 判断を変える一次資料を優先する。原著、規格、開発元の仕様・実装、実際の利用結果を参照する。既存調査を再利用し、根拠のURLと該当条件を示す。見つからないことを反例なしと同一視しない。
3. 現行案が失敗する経路を具体化する。依存、権限、境界入力、途中失敗、データ消失、回復不能、誤判断、費用超過を対象に応じて追う。推測と発生済み障害を分ける。
4. 既存外部実装・別原理・現状維持も探す。前提が崩れたときの影響と最小修正・代替案を示す。比較が必要なら [adjudicate](../adjudicate/SKILL.md) へ渡す。
5. 重大な指摘から返す。主張、発生条件、根拠、利用者への影響、修正・停止・置換候補を示す。反証成立、調べた範囲で反例なし、証拠不足を区別する。

## 反例の着眼点

- 継続実行：取得失敗の差分なし扱い、古い結果の最新扱い、二重反映、未完了工程の飛ばし、複数書き手、再開不能、外部CLIの上書きによる手修正消失。
- 知識・データ：同名別対象の統合、出典欠落、旧版への誤誘導、結合の多重化、形式変換による意味の変化。
- UI・文章：最後の操作ができない、空やエラーが成功に見える、根拠が主張を支えない、説明削減で必要な判断が失われる。
- 技術白書：推奨案に不利な一次資料、比較条件の不一致、結論が逆転する条件を [didactization](../didactization/SKILL.md) に返す。
