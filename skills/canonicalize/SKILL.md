# 正本とデータ契約

## 手順

1. 現行の読み手・書き手・正本と重複定義を確認する。
2. 一つの正本と必要な識別子・粒度・型・出典・時点を決める。不要な項目を増やさない。
3. データと参照元を新しい正本へ移し、既存の利用経路を切り替える。
4. 代表入力で読込・保存・再処理・重複防止を確認してから旧定義を削除する。

## 形式と再開

OKF、Obsidian、dbt、frontmatterは対象が必要とする場合だけ採用する。定期処理の状態は既存Issueか実行履歴にまとめる。回答待ちがなければ質問台帳を作らない。

## 完了

読み書きが正本に統一され、必要な履歴と参照が維持されている。
