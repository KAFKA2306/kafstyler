# 正本・意味・引き継ぎの統一

同じ意味の正本を二つ持たない。検索・判断・更新に必要な情報を保ち、派生物や要約を別の正本にしない。

## 設計と移行

1. 答える問い、対象、粒度、管理者、実入力、読取・書込経路を特定する。エンティティのID、関係、属性、操作、単位、欠損の意味を定義し、既存語彙を優先する。
2. 同じ対象の実装・設定・文書・台帳から権威ある定義を選ぶ。正本の場所、更新者・更新経路、必要な出典・時点・来歴を定める。
3. 台帳は一行のキー、状態遷移、訂正と再入力時の照合方法を定める。マスターはID、正とする属性、有効期間を定める。同名の異なる対象を統合しない。集計では粒度と結合の多重化に注意する。
4. 旧版にしかない情報を移し、読取・書込・参照を新正本へ切り替える。利用者データ、識別子、出典、訂正履歴を保持する。不要な互換経路は [decommission](../decommission/SKILL.md) へ渡す。

## 案件の引き継ぎ（Project as Code）

Concept（目的・要求・採用判断）、Definition（仕様・コード・データ）、Facade（README・図・報告）を区別する。MISSIONは目的、Issueは仕事、Gitは変更、公開先は成果の正本とする。元の会話なしで再開できるよう、既存案件ID、目的と対象の参照、反映済み成果、残る工程、権限・停止条件を必要な分だけ渡す。独立した台帳を増やさない。

定期実行は入力ID・更新識別子と処理済み位置を既存正本から復元する。取得失敗を差分なしにしない。判断待ちは質問、回答者、必要な判断、再開先を既存Issue等に結ぶ。

## 知識・文書・分析データ

- Vaultと文書：正本の物理パス・更新元を一つにし、代表的な問い、現在の文書、重複候補、出典を結ぶ。分類、索引、タグ、別名、相対リンクは実際の検索・利用に必要なものだけにする。旧資料の来歴を保持する。
- OKF：採用版の公式generate/consume Skillで構造化・検索する。ルート目次、文書type、相対リンク、来歴は [実行契約](../../commands/knowledge.md) に従う。一律移行しない。
- Knowledge Compiler / Obsidian：原資料抽出と知識への採用を分ける。検索は mise run vault-query QUERY --vault PATH --json、取り込みは mise run vault-extract SOURCE --vault PATH、認可済み保守は mise run vault-maintain。訂正は対象と新旧記述が特定された場合に限る。
- dbt：既存sourceとrefで依存を定義し、粒度とキーを決め、重複計算を統合する。採用案件のモデルだけを既存dbt操作で更新する。
- 研究・白書：主張を一次URL・引用箇所、数値を単位・測定条件・時点に結ぶ。観測、予測、仮説、未確認を区別して [didactization](../didactization/SKILL.md) へ渡す。

返すものは正本・意味・ID・更新経路・移行対象・残す情報・再開先。追加記録は既存記録にない不可欠なものだけ。
