# 致命的な欠陥のレビュー

任意の出力で人が読む文章には[imozの執筆・推敲ルール](../../BIBLES.md#imozの日本語編集)を適用する。[出力の共通基準](../../MISSION.md#出力の共通基準)

1. 最初に論文調査、文献調査、Web検索をすべて行う。関連論文の原著、書籍・規格・技術報告、開発元の最新版と実装を調べる。出典の一次URL、版、比較に使える条件を記録し、見つからなかった資料も明記する。
2. 現行を置き換える前提で、根拠のある外部手法や既存実装を探す。期待する結果と成立に必要な前提を定め、同じ条件で現行と候補を比較する。前提が崩れたときに最も影響が大きい箇所から調べる。
3. 実物、実際の入力、一次資料を使い、利用者が普段使う経路を最初から最後まで追う。結果が変わる箇所では依存関係、権限とデータの境界、途中失敗、再試行、復旧を確認する。
4. 同じ証拠から最も有力な対立仮説を立てる。現実に起こり得る反例か境界事例を示し、どの観測で仮説を見分けられるかを定める。反例や再発を実行して測れる場合は、[`kafstyler:benchmark`](../benchmark/SKILL.md) を呼ぶ。仮説を判別する入力、手順、期待する観測を渡し、結果を指摘の根拠に使う。
5. 致命的な指摘から挙げる。中核の結果が成り立たない、普段の利用経路で動作しないか安全に使えない、復旧できない重大な損失が生じる場合を含む。指摘ごとに発生条件、実際の根拠か正確な再現手順、影響、最小の修正か結論を決める確認を記す。実測していないリスクは未確認とする。
6. 置き換え、修正、停止の判断と、その根拠を示す。合格条件を満たす候補が確認できた場合は、置き換える対象と移行後の確認を示す。根拠のある致命的な指摘が0件なら、重要な確認と影響の最も大きい未確認事項を示す。
