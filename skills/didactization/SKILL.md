# 知見の教材化と文章編集

独自知見の教材化と原意を守る文章編集を区別する。後者に新たな発見を要求しない。

## 発見を汎用原則に変える

1. 原資料、実際の観測、失敗、実験結果、訂正、反例から新しい知見を抽出する。対象・条件・出典を保ち、AIの着想と実測を混同しない。
2. 「どんな条件で、何をすると、何を防げる／改善できるか」を一文にする。なぜそうなるか、現象→原因→機構を根拠の範囲で説明する。経験則、因果説明、仮説、価値判断を分ける。
3. 成功例だけでなく失敗例、比較対象、適用外の条件を示す。必要なら [disprove](../disprove/SKILL.md) の反例を取り込む。
4. 別案件で使えるよう、必要な入力・操作・判断・出典を具体化する。汎用化不能な案件情報は利用先に残す。独自知見がなければ既存文書へ統合し、出典と訂正履歴を守る。

原資料抽出と意味の統合は別。抽出資料をそのまま真実と認定せず、[canonicalize](../canonicalize/SKILL.md) の正本に新知見・訂正・反例だけを統合する。

## 記事・教材・白書

- 読者の問いと最後にできるようになる判断・操作から逆算し、基礎→原理→具体例→適用条件→次の操作を必要な順に並べる。教科書風の体裁を目的にしない。
- 技術白書は読者の採否判断、問題と原因、結論と主要根拠、仕組み、選択肢、条件をそろえた既存比較結果、制約・反例・未確認事項を扱う。数値に単位・測定条件・時点を添える。宣伝文句や根拠のない章を増やさない。
- [reconceptualize](../reconceptualize/SKILL.md) の読者目的、[canonicalize](../canonicalize/SKILL.md) の出典と正本、[disprove](../disprove/SKILL.md) の反例、[adjudicate](../adjudicate/SKILL.md) の採否根拠を必要に応じて使う。

## 原意を守る推敲

主張、数値、条件、時点、不確実性、引用、IDを維持する。結論を先に置き、具体的な主語・動詞・平易な言葉を使う。見出しだけでも問いと答えが分かるようにし、同じ概念には同じ用語を使う。重複、根拠なき断定、定型句、無意味な装飾を削る。ただし必要な手順・判断・条件は削らない。

README・PR・UI・報告では、人の用事、解決の仕組み、最初の操作、実際の成果を示す。結果・推測・失敗・古い状態を分け、未実行を実績としない。Project as CodeのFacadeは仕様・データ・実装の参照を保持し独立した正本にしない。工程や依存を文章より短く説明できる場合のみMermaidを使う。

完成稿、必要な根拠、適用条件、公開先を返す。原典：[使命・評価・執筆](../../bibles/mission-eval-writing.md)、[設計とUI](../../bibles/design-and-ui.md)。
