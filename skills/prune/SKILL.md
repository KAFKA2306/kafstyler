# 不要なファイル・コード・文章を削る

依頼の範囲で、不要と確認できたファイルをその場で削除する。調査・提案のみの依頼では削除候補と根拠を示す。利用者が普段の入口から必要な操作を続けられ、仕様・実装・設定・文書が一致する状態を保つ。

任意の出力で人が読む文章には[imozの執筆・推敲ルール](../../BIBLES.md#imozの日本語編集)を適用する。[出力の共通基準](../../MISSION.md#出力の共通基準)

着手前に、かふかのZenn記事を3本読み、対象に当てはまる整理基準を選ぶ。

- [なぜAIに任せるほど、あなたのコードは複雑になるのか](https://zenn.dev/kafka2306/articles/2026-08-16-ai-added-decision-cost-audit) 重複する指示・検証・状態・分岐を洗い出し、削除後も機能・正しさ・必要な証拠が揃うかを確かめる。 [聖典台帳](../../BIBLES.md#aiが増やす判断箇所)
- [AIに同じ指示を繰り返すのをやめた。Issue駆動開発という最小運用](https://zenn.dev/kafka2306/articles/issue-driven-development) 終わった変更の経緯をIssueに残し、現在の仕様として必要な記述を正本に集約する。 [聖典台帳](../../BIBLES.md#issue駆動開発)
- [AIを「過保護」にするな。スタックトレースを聖典とする開発規律 "Crash-Driven Development"](https://zenn.dev/kafka2306/articles/11cd731eebded1) 障害の原因を隠す広すぎる例外捕捉やフォールバックを見直し、根本原因を観測できる形にする。 [聖典台帳](../../BIBLES.md#失敗原因が見える実装)

1. 対象のファイルを一覧にする。Gitでは `git status --short` と `git ls-files` を使い、先頭がドットのファイルやディレクトリも確認する。普段使うコマンドや画面、配布物、仕様・データの正本を把握し、削除前に必要な挙動と入出力を確かめる。KAFKA2306のWeb UIでは、[かふかのデザインパターン](../../BIBLES.md#かふかのデザインパターン)から設計・同期の手順を開き、共通部品やトークンと重複する利用側の定義を確認する。
2. 正本と重複する文書や設定、利用先が現行版に切り替わった旧版、役目を終えた作業メモや一時出力、配布に使わず再生成できるファイル、使われない資産・コード・ラッパー、同じ確認を繰り返すスクリプト・テスト・CIを探す。同じ役割のフォルダは既存の管理先に統合する。既存の[評価結果](../benchmark/SKILL.md)も使い、置き換えが済んだか確かめる。ファイル内では、結論の繰り返し、判断に使わないバッジ、未使用のプレースホルダー、読者の判断や操作に不要な作業説明を削る。一つのプログラムに一つの仕事を持たせ、必要に応じて標準入出力でつなぐ。
3. 候補ごとに、移行先の正本、再生成の手順、または用途を終えた根拠を確かめ、普段の入口から使われているかを調べる。文字列検索に加え、動的読み込み、ファイル名のパターン指定（glob）、ビルド・配布設定、CI・定期実行、公開パスからの利用も確認する。
   - 未コミットの変更があるファイル、未追跡・無視対象の作業物、再取得できないデータ、利用の有無が確認できないファイルは保留する。依頼で明示された未追跡・無視対象の生成物は、再生成手順と利用経路を確認して扱う。
   - [共通の連携手順](../../AGENTS.md#コマンドの連携)に従い、削除前に [`kafstyler:scrutiny`](../scrutiny/SKILL.md) へ候補、根拠、正本、残す入口と出力を渡す。指摘で根拠が崩れた候補は保留し、他の候補は進める。
4. 削除する箇所にだけある事実、指示、適用条件は正本へ移す。不要と確認できたファイルはパスを指定して削除し、空になった不要なフォルダも片づける。インポート、リンク、設定、呼び出し元は同じ変更で更新する。Gitでたどれる旧版や完了済みの経緯は履歴で参照する。必要なファイルは件数目標のために削らない。
   - 整理によってタイトル・見出し・用語を変更したら、[`kafstyler:humanizer`](../humanizer/SKILL.md#タイトル見出し用語の見直し) に変更箇所、正本、読者を渡す。校正結果を反映し、更新した参照先も確かめる。
5. 削除対象が実際に消えたことを差分とファイルの有無で確かめ、残した入口を同じ入力で実行する。仕様・実装・設定・文書を正本に照合し、参照切れや挙動の変化があれば直すか、問題を起こした削除を戻す。比較が必要で同じ確認の結果がまだなければ、[`kafstyler:benchmark`](../benchmark/SKILL.md) に削除前の入力と観測結果、入口、合格条件、変更範囲を渡す。削除したパスと件数、確認結果、保留の理由を示す。削除がゼロ件なら、調べた範囲と残した理由を示す。
